# Начало работы с ContentFactory

Создавайте видео, изображения, озвучку, музыку и редактируемые композиции с
помощью AI-агента и ContentFactory. Инструкции самого скилла написаны на
английском, а общаться и создавать материалы можно на выбранном вами языке.

## Четыре шага для начала

1. Установите Python 3.11+ и актуальный Codex CLI. Выберите существующую папку проекта.
2. [Скачайте ZIP-файл репозитория](https://github.com/ContentFactoryAIArt/Skills/archive/refs/heads/main.zip)
   и распакуйте его либо клонируйте репозиторий:

   ```sh
   git clone https://github.com/ContentFactoryAIArt/Skills.git
   cd Skills
   ```

3. Из распакованной или клонированной папки запустите команду, указав
   существующую папку своего проекта:

   ```powershell
   python scripts/connect.py --workspace "C:\Projects\MyVideo" --language ru
   ```

   В браузере войдите в ContentFactory и выберите проекты, права и срок доступа.
4. Откройте или перезагрузите проект в Codex и напишите:

   > Используй $contentfactory-video для рекламного ролика на 30 секунд на русском.
   > Работай в выбранном проекте и покажи ожидаемые расходы до платных операций.

Если установщик сообщает, что единый адрес пока недоступен, нужно дождаться
соответствующего обновления сервера ContentFactory. `--install-only` подготовит
скилл, но для творческой работы всё равно понадобится действующее соединение.

У ContentFactory один публичный адрес MCP для Media, Generate и Compose:

```text
https://content-factory.art/mcp
```

Выберите Streamable HTTP в своем агенте. Войдите на странице ContentFactory
в браузере, выберите проекты, права и срок доступа. Платные операции включайте,
только если они нужны. Вход в аккаунт и подтверждение прав MCP могут быть
отдельными экранами одного процесса подключения.

Единый адрес требует соответствующего обновления сервера. Скрипт проверяет
публичные OAuth-метаданные до начала авторизации. Если адрес пока недоступен,
он сообщает об этом, не добавляя старые подключения и не ослабляя защиту.

## Codex: Установка Скриптом

Нужны Python 3.11+ и официальный Codex CLI с параметрами
`--oauth-client-registration` и `--oauth-resource`. Запустите скрипт из папки
репозитория, как показано выше; `--client codex` указывать необязательно.

В Windows укажите существующую папку в кавычках, например
`--workspace "C:\Projects\MyVideo"`. Скрипт установит
`.agents/skills/contentfactory-video` в проект и добавит сервер
`content-factory` штатной командой Codex. Настройка MCP хранится в обычной
для клиента области конфигурации; сам скилл устанавливается только в проект.

Если сервер с таким именем уже включен и его адрес совпадает, скрипт сохранит
подключение без повторного добавления и входа. Другой адрес или особая настройка
авторизации не перезаписываются. Существующие файлы скилла должны совпадать
с комплектом; пользовательские изменения сохраняются.

Предпросмотр без изменения файлов, сети и чтения конфигурации клиента:

```sh
python scripts/connect.py --workspace /path/to/your/project --language ru --dry-run
```

Установка только инструкций, если MCP уже подключен в приложении:

```sh
python scripts/connect.py --workspace /path/to/your/project --language ru --install-only
```

Обновите список скиллов проекта в Codex и вызовите `$contentfactory-video`.
Например: «Используй $contentfactory-video для рекламного ролика на 30 секунд
на русском. Работай в выбранном проекте и не превышай указанный мной бюджет».
Первый запрос MCP проверяет реальный доступ: установка сама по себе не доказывает
успешную авторизацию или доступность платного провайдера.

## Другие MCP-Клиенты

В клиенте с поддержкой удаленного Streamable HTTP MCP, OAuth и PKCE добавьте
указанный адрес как один сервер и пройдите штатный вход через браузер. Если
клиент предлагает способ регистрации, выберите Dynamic Client Registration
(DCR). Не вставляйте пароли, bearer-токены и секреты клиента в переписку.

Установите всю папку `skills/contentfactory-video` штатным механизмом скиллов.
Для Claude Code папка проекта: `.claude/skills/contentfactory-video`;
сам сервер настройте через MCP-настройки клиента и авторизуйте через `/mcp`.
Документированная команда для терминала Claude Code:

```sh
claude mcp add --transport http content-factory https://content-factory.art/mcp
```

Затем выполните `/mcp` внутри Claude Code для авторизации. Если сервер уже
настроен на этот адрес, используйте существующее подключение.
Python-скрипт пока автоматизирует только Codex. Клиенты без поддержки скиллов
могут работать с MCP, но этот комплект не устанавливает в них скилл.

## Без Повторного Входа

Добавление или обновление инструкций скилла не требует OAuth. Новая беседа
не требует заново добавлять серверы. Клиент хранит делегированный доступ до
истечения срока или отзыва; изменение прав аккаунта или проекта тоже может
прекратить доступ. Сохраняйте одно подключение и используйте управление клиента.

После подтвержденной ошибки из-за истекшего, отозванного или незавершенного
разрешения можно явно повторить вход:

```sh
python scripts/connect.py --workspace /path/to/your/project --language ru --login
```

Это восстановление доступа, а не обязательный шаг после каждой установки.
`codex mcp add` уже запускает OAuth; после успешного подключения не требуется
автоматически выполнять второй `codex mcp login`.

Скрипт рассчитывает на автоматическое открытие браузера Codex и скрывает
исходный вывод клиента. Если браузер не открылся, нажмите Ctrl+C. Запись сервера
могла уже сохраниться. Для такого подключения запустите ручной вход в своем
терминале:

```sh
codex mcp login content-factory --oauth-client-registration dcr --no-browser
```

Следуйте инструкциям Codex по открытию ссылки и передаче callback-адреса
в терминале; не вставляйте эти адреса в переписку. Если Codex явно сообщает,
что сервер не существует, один раз добавьте его и пройдите штатный вход:

```sh
codex mcp add content-factory --url https://content-factory.art/mcp --oauth-client-registration dcr --oauth-resource https://content-factory.art/mcp
```

Этот способ нужен только после ошибки или прерывания установки и при доступном
едином серверном адресе. После ручной настройки используйте `--install-only`
для установки инструкций без повторного входа.

Старые разрешения `/mcp/media`, `/mcp/generate` и `/mcp/compose` привязаны
к прежним ресурсам. Переход на `/mcp` требует одного нового согласия. Проверьте
единое подключение, затем отключите старые записи в клиенте. Скрипт не удаляет
старую конфигурацию и не отзывает токены автоматически.

Управление токенами: https://content-factory.art/settings/tokens.
Выбирайте срок, достаточный для вашей работы. Бессрочный доступ остается
необязательным, требует явного согласия и может быть отозван. Единый адрес
сохраняет границы проектов, права, ограничения расходов и проверку PKCE.

## Инструменты и Приватность

Скилл использует только инструменты подтвержденного сервера
`https://content-factory.art/mcp`. Одного названия инструмента недостаточно.
Если клиент скрывает настоящий адрес, сначала подтвердите это подключение.
Штатные подтверждения клиента сохраняются; скилл не является песочницей
и не заменяет серверную проверку прав.

Сторонние AI, браузерные инструменты, локальная обработка и обходные загрузчики
не используются. Локальные файлы загрузите через ContentFactory и выберите
созданные ресурсы. Недоступную функцию или проверку агент обозначит явно.
Скрипт подключения работает отдельно от творческого скилла: проверяет публичные
метаданные, запрашивает у CLI конфигурацию только одного сервера и передает
OAuth самому клиенту. Он не читает хранилища учетных данных, не получает токены,
не меняет другие серверы и не печатает исходную конфигурацию.

Инструкции для начала работы доступны на всех десяти языках публичного сайта.
Язык общения и творческого результата задает пользователь.

Официальная документация клиентов: https://developers.openai.com/codex/mcp/,
https://code.claude.com/docs/en/mcp и https://code.claude.com/docs/en/skills.
