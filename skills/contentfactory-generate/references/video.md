# Choose, generate and verify a moving shot

## Default to premium production quality

1. From the director's shot card, identify required reference slots, observable action, subject fidelity, aspect, duration, resolution and audio needs. Treat these as compatibility filters. Check project rights, authorized limits and remaining budget after accounting for settled, reserved and uncertain costs and the final Gemini audit.
2. Use `generation_models_list` for the requested video intent and follow pagination as needed. Shortlist current flagship, Pro or highest-quality variants, including full Seedance 2.5 when exposed. Treat model names as search hints. Compare evidence from accepted project takes first, then relevant current comparisons or provider samples. Match the benchmark task to the shot, such as reference-to-video for identity or image-to-video for product motion. A text-to-video ranking alone says little about an object that must retain exact reference geometry. Check dedicated image-to-video or motion-control entries when a flagship's generic generation route exposes no media slots.
3. Use `generation_models_describe` for candidates that could win. Prefer the strongest motion, identity, continuity and output controls for this shot at the highest suitable production quality. If two eligible routes have comparable quality evidence, prefer the higher production tier, then the higher quote for the same requirements within that tier. A high quote alone does not establish fidelity. Use Fast, Lite, Standard or economy routes when the user opts for speed/economy, or as a disclosed fallback when premium is a preference and a qualifying premium route is unavailable. If the user requires a premium route, retain that constraint until they authorize changing it.
4. Quote the exact viable request with `generation_preflight`. Preflight comparable finalists when quote is the deciding factor. If the first choice is incompatible, unconfigured, unpriced or exceeds the available ceiling, compare the next strong qualifying route, disclose the reason and resulting tradeoff, and keep required reference slots and output requirements intact. Use a compatible authored route or state the specific unfilled beat if none qualifies. A materially changed staging plan returns to approval.

## Bind the reviewed shot

Discover and describe each operation before invoking it. The envelope's `contractRevision` and the model's `modelContractRevision` identify separate contracts. `generation_models_describe` returns the model schema and allowed source slots. Build `generation_preflight` and `generation_create` with the same `submission`, `modelId`, `modelContractRevision`, `intent`, `inputJson` and actual source bindings. Use the project-owned immutable sources and slots reported by the schema. For declared media leaves, put the JSON value `{"media_ref":"binding-id"}` at the supported path in `inputJson`, and a matching `sources[].bindingId` with the accepted owned file/image/video variant. Preserve approved first/last or identity references. Do not silently turn a reference-conditioned shot into text-only generation.

Write the prompt for this take from the shot card. Describe starting pose and framing, the subject's physical action over time, the readable end state and the continuity that must hold. Put camera, duration, audio and other controls in real model fields where the schema provides them. Example: “Locked medium close-up. The hand turns the cap clockwise until it seats flush. Keep the bottle silhouette, etched label, fingers and grip continuous. Hold long enough to see the closed cap.” For a multi-shot input, use that mode only when the schema supports it and the approved choreography can be verified.

Recover the matching [approved package](../../contentfactory/references/director-approval.md), then submit one bounded take or the hardest approved beat first. Preflight is advisory. Retain the exact idempotency key, operation receipt, request controls and reference pins. Wait on that operation. Use the result receipt to identify the owned asset/file. For uncertainty or a failed import, use [recovery](../../contentfactory/references/execution.md).

## Accept or repair

Play the whole returned take and inspect the action from setup through result. Where feasible, inspect the start, action and result frames at known times for detail, then check motion between them and continuity at adjoining shots. If only frames are available, record their observed details and leave motion unverified. Look for artificial holds, subject motion hidden by camera movement, hand/contact errors, identity drift, wrong geometry, clipped action, text artifacts and unusable sound. Keep the observation tied to the exact asset and interval.

Record a short take note with expected action, observed action, evidence coverage, and keep/revise/replace. For a retake, name the cause you can address and change the relevant instruction, conditioning or route. Reconcile prior receipt and spend first. Reuse unchanged accepted inputs. If a material approved element changes, show the revised beat before new generation. Never fill a missing moving beat with a flat camera move or slideshow.
