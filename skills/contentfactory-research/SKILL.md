# contentfactory research

Use the connected ContentFactory MCP server and stay within the user's selected projects and authorization. Search `operations_list` for the needed operations, following continuation anchors when present; use `operations_describe` to obtain the full input schema and current contract revision. Schema descriptions do not install new native tools. Invoke read operations with `operations_read` and effectful operations with `operations_execute`, supplying the exact revision and full arguments. If the contract changed, rediscover it before proceeding. Check the MCP error indicator and typed result status; a transport success alone does not prove the operation succeeded. Preserve native media or resource blocks when returned.

Use the requested sources and selected project. Discover the current research operation and its preflight/receipt contract; respect provider charges and the user's spending limit, including reserved or uncertain charges. Submit only the requested collection or search. Preserve the idempotency key for identical retries and poll a durable content-operation receipt after an uncertain outcome. Return useful source metadata and owned media references; do not assume all provider results contain downloadable media. This skill covers ContentFactory research, not general research using unrelated tools.

For Telegram group or forum history, discover `telegram_messages_collect`. It reads bounded oldest-first text/metadata from one public username-addressable group, forum or channel. Supply `chat`, `maxMessages` and optional `startDate` from the live schema; preflight the equivalent `research.telegramMessages` request. Read `research.telegramMessages` from the completed receipt and preserve source URLs/IDs plus any returned `threadId`, `topicName`, `replyToMessageId` and `replyQuote`. Missing fields remain unknown. Private invites and caller Telegram sessions are unsupported. Limits bound returned rows; bounded or empty results never establish complete chat/topic coverage. Report actual coverage and charge before increasing a scan or retrying.

`telegram_posts_collect` reads public channel web previews with its documented filters; it does not read group/forum history. An empty successful dataset or a group landing page does not prove that messages were inspected. `telegram_media_download` separately imports selected attachments under its current URL and bounded-scan contract. Text collection alone does not import or verify playable media.

For media from exact public posts, prefer `telegram_post_media_download` when web-preview coverage is sufficient. Supply `input.postUrls` with 1..50 exact `https://t.me/chat/message` or `https://t.me/chat/topic/message` links; this operation has no history-scan limit or start date. Preflight `research.telegramPostMedia`. The source supports photos, voice audio and short videos up to 60 seconds; it does not establish original quality or complete albums and cannot replace the history attachment operation for arbitrary files or longer videos. Read owned files in `research.media` and typed `research.telegramMediaFailures` from the settled receipt. Callers supply only Telegram post links: direct download URLs, media arrays, actor IDs and provider credentials are not accepted. The worker resolves and downloads media only from the pinned source's validated output; signed source URLs remain private.

A settled Telegram download can remain `FAILED` while returning complete independent files in `research.media` and `artifacts`. Inspect typed `research.telegramMediaFailures` for the selected URL, request index, failed message ID and reason; incomplete albums expose no partial album. Use the returned owned files only after checking their immutable size/digest and media inspection. Do not discard usable files or report the entire selection as successful. For an older settled `source_media_resolution` rejection, discover `content_operation_result_recover`: it can read the existing completed source dataset and import available files with current project write access, without a new provider run or charge. Poll its separate recovery receipt; retain the original failed receipt and settled charge. Missing source files still require a different source or a separately authorized collection, never an automatic paid retry.

Build bounded download arguments from the current schema, including the source URL field's exact shape and required message limits for a history-based Telegram download. Source variants have different contracts; preserve arrays where supported, and select optional quality/format values only from the current operation or provider capability contract. If validation rejects a request, inspect its field violations and the relevant schema before changing it; do not infer an unsupported batch or option from a generic error. A quote's maximum reservation is not an actual charge; narrowing the source does not necessarily lower its ceiling. Public Telegram previews may omit full large videos, and throttled YouTube pages may expose only titles/descriptions. Label findings from that evidence accordingly rather than claiming watched footage or measured performance. An unavailable tariff remains a blocker until a relevant configuration changes; do not repeat unchanged preflights or substitute a paid import without the requested spending authorization.
